# Data contract

Collections: `users`, `buildings`, `meters`, `readings`, `bills`, `alerts`, `maintenanceTickets`, `actionVerifications`, `sustainabilitySnapshots`, `settings`. Records have `id`, `created_at`, `updated_at`, `created_by` where created by APIs. Dates are ISO strings; timestamps have timezone offsets (UTC for normalized reading storage). Currency INR; no inferred unit conversions beyond m³ to litres for water balances.

In PostgreSQL each collection is a table defined in `backend/app/schema.sql`; `maintenanceTickets`, `actionVerifications` and `sustainabilitySnapshots` become `maintenance_tickets`, `action_verifications` and `sustainability_snapshots`. Dates and timestamps are typed columns (returned to the API as ISO strings, timestamps in UTC); lists and nested records such as `quality_flags`, `history` and `evidence_snapshot` are `jsonb`.

- users: Supabase Auth user ID as ID, name, role (viewer/operator/admin), active.
- buildings/meters: evidence-backed ID, name, resource, location, source_ref, connectivity (unverified/manual/csv), notes. No physical meter is invented by registry seed.
- bills: account, invoice, meter_id, previous/current reading dates, kwh, optional kvah, total_inr, optional demand_kva/demand_charges_inr, energy_rate and explicit rate unit, source, source_ref, quality_flags. ID hash of account+invoice; duplicates rejected. Original bill values immutable via this API.
- readings: meter_id (or documented logbook channel), category (RO input/product/reject, blocks 1–3, electricity), unit, interval/cumulative kind, value, start/end, source, source_ref, quality_flags. ID hash of meter/category/kind/normalized end timestamp. Interval start is required; cumulative deltas are computed within matching meter/category/unit/demo partition. Negative deltas flag resets, not negative consumption. Quality-flagged values excluded from balance calculations.
- alerts: rule IDs, status, updated_at and history. Evidence is recalculated from immutable source records and current thresholds. If a threshold changes, historical acknowledgments remain in storage but only currently-triggered rules display. Expected comparisons and hypotheses are generated, not measured facts.
- maintenanceTickets: title, alert_id, owner, priority, status, findings, corrective_action, post_start/end and append history. Closing requires findings, action and planned post-window. Closure alone does not verify savings.
- actionVerifications: immutable baseline/post IDs and complete evidence snapshot, context, comparability confirmation, requested and evaluated status, resource unit/reduction, duration normalization, reviewer, financial estimate and cost basis. Direct interval evidence only for readings; cumulative registers must first be normalized and documented. Different units, meters, categories, overlapping windows, gaps or repeated evidence rejected. Verified post evidence cannot be credited twice. Negative outcomes are preserved as increases. Context review is an operator attestation, not an independent audit.
- sustainabilitySnapshots: reserved for future scheduled snapshots; current score is computed live. No snapshot records are fabricated.
- settings/global: increase_pct, stale_days, water_balance_pct, optional marginal_kwh_rate/tariff_basis, scenario_pcts, score_weights.

`actual` is reserved for commissioned ingestion; manual readings and CSV imports cannot claim live hardware. `imported` bills retain the source PDF reference. `demo` is synthetic and excluded from observed bill overview, alert generation and verified outcomes. Demo balances are labelled separately. Source logbooks with unresolved units remain in source-review documentation, not the measurement collection.

Verification math: baseline total / baseline duration × post duration − post total. All resource reductions may be positive or negative; financial results use an explicitly supplied marginal rate and remain estimates. Electricity bill kVAh tariffs must not be passed as INR/kWh without a supported conversion. Demand effects are deliberately not inferred.
